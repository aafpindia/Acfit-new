1. EXECUTIVE SUMMARY & DUAL-ENGINE ARCHITECTURE OVERVIEW
====================================================================================================
ACFIT Academy LMS is a modern web application engineered to deliver certification programs for fitness
professionals (e.g., NASM Certified Personal Trainer - CPT, Certified Nutrition Coach - CNC, Certified
Fitness Trainer - CFR PRO, and specialized workshops).

The application is architected around a "Dual-Engine Hybrid Pattern":
1. Live Database Mode (Supabase PostgreSQL): Activated when VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
   are supplied. Data is persisted to normalized relational tables (profiles, courses, modules, lessons,
   assessments, enrollments, progress, attempts, certificates, payments, announcements, system_settings).
2. Offline / Mock Simulation Mode (LocalStorage + Zustand): Activated when Supabase is not configured or
   when network calls time out. State is held in Zustand memory and partially serialized to LocalStorage.

System Bootup Sequence:
- main.jsx boots the React 19 tree inside BrowserRouter and QueryClientProvider.
- AuthProvider (src/contexts/AuthContext.jsx) initiates apiClient.auth.me().
- If a Supabase session exists, it queries the `profiles` table for user role ('user' vs 'admin').
- Immediately calls `useLmsStore.getState().syncFromSupabase(user)` and `subscribeToRealtime(user)`.
- Global routes (src/routes/index.jsx) mount with code splitting via React.lazy() and Suspense.
- Route Guards: ProtectedRoute enforces valid session; AdminRoute enforces role === 'ADMIN'.

2.1. Landing Page & Course Discovery
------------------------------------
- The visitor arrives at `/` (LandingPage.jsx).
- The hero section displays ACFIT accreditation badges (NASM, CFR PRO), partner gym logos (Gold's Gym,
  Slam Fitness, Anytime Fitness), and an animated counter (CountUp.jsx).

2.2. Authentication, Session Security & Idle Enforcement
--------------------------------------------------------
- Public auth routes: `/login`, `/signup`, `/forgot-password`, `/reset-password`.
- Login Flow:
  1. Student enters email and password into `Login.jsx`.
  2. Dispatches `signIn(email, password)` via `AuthContext.jsx` -> `apiClient.auth.login`.
  3. Supabase validates credentials with `supabase.auth.signInWithPassword`.
  4. Profile data is fetched from `profiles` table to determine user role.
  5. Session timing starts: `initSessionSecurity()` writes `{ startTime, lastActive }` to localStorage.
  6. Inactivity timer starts: 3600 seconds (60 minutes). Mousemove, keydown, and scroll events throttled
     to 10-second intervals reset the inactivity clock. If 0 seconds remain, `signOut()` is enforced.
  7. On success, user is redirected to `/app/courses` (or previous route stored in `location.state.from`).

2.3. Course Details & Curriculum Inspection
-------------------------------------------
- Route: `/courses/:courseId` or `/app/courses/:courseId` (CourseDetails.jsx).
- Fetches course data via `useCourse(courseId)` from TanStack Query and `lmsStore`.
- Displays:
  - Hero banner with title, instructor, level, duration, and price in INR (e.g., ₹0 for free or ₹14,999).
  - Syllabus accordion: Full breakdown of Modules and Lessons with lesson type badges (Video, Rich Text,
    PDF, PPT, Live Class, Quiz).
  - Accreditation benefits (NASM CEU points, lifetime valid digital certificate).
- Dynamic CTA:
  - If already enrolled -> "Resume Learning" button leading to `/app/learning/:courseId`.
  - If course is Free (price === 0) -> "Enroll for Free" button.
  - If course is Paid -> "Enroll Now — ₹[Price]" button triggering Razorpay payment modal.

2.4. Checkout, Razorpay Payment Gateway & Seat Enrollment
---------------------------------------------------------
- Free Enrollment Flow:
  - Dispatches `enrollInCourse(course.id, user.id, freePaymentPayload)`.
  - Also dispatches `enrollMutation.mutateAsync(...)`.
  - Writes enrollment to `enrollments` table and ₹0 record to `payments` table.
  - Navigates immediately to `/app/learning/:courseId`.
- Paid Enrollment Flow:
  1. Student clicks "Enroll Now".
  2. `CourseDetails.jsx` calls `openCheckout(...)` from `src/services/razorpayService.js`.
  3. Dynamically injects `https://checkout.razorpay.com/v1/checkout.js` if not already loaded.
  4. Opens Razorpay standard checkout popup with amount = `price * 100` (in paise).
  5. If Razorpay keys are absent in environment, launches the built-in high-fidelity interactive
     simulation modal (`#rzp-simulator-backdrop`) allowing test card/UPI payment.
  6. Upon completion handler callback, receives `razorpay_payment_id`.
  7. Client dispatches `enrollInCourse(course.id, user.id, paymentPayload)` and `enrollMutation.mutateAsync(...)`.
  8. Enters student into `enrollments` table and payment entry into `payments` table.

  8. LiveClassPlayer (live-class):

3.4. Bunny Stream Video Ingestion (TUS Protocol, Chunking & CDN Delivery)
------------------------------------------------------------------------
- Component: `src/components/ui/VideoUploadDropzone.jsx` and `src/services/bunnyService.js`.
- Implements 6-step Bunny Stream pipeline:
  1. Admin drops a video file (MP4, MOV, MKV) onto the dropzone.
  2. Calls Bunny REST API (`POST https://video.bunnycdn.com/library/{libId}/videos`) with title to create
     a Bunny Video GUID.
  3. Generates SHA-256 authorization signature: `SHA256(LibraryId + ApiKey + ExpirationTimestamp + VideoId)`.
  4. Initiates resumable TUS upload (`tus-js-client`) to `https://video.bunnycdn.com/tusupload` with 5MB chunks.
  5. UI displays real-time animated upload percentage and upload speed.
  6. Upon TUS completion, Bunny transcodes video into adaptive HLS bitrates (360p, 720p, 1080p).
  7. Video GUID and HLS URL are automatically linked to the lesson's content object.

4. SYSTEMIC FLOW LAGS, BOTTLENECKS & ARCHITECTURAL FRICTION
====================================================================================================

4.1. Heavy State Synchronization Loop (Zustand + Supabase Resync)
-----------------------------------------------------------------
- Issue: Every single state mutation across the app triggers a complete global resync:
  `await get().syncFromSupabase()`.
- What happens: When a user completes ONE lesson, `markLessonComplete` executes:
  1. Writes to Supabase `progress` table.
  2. Calls `syncFromSupabase()`.
  3. `syncFromSupabase` issues 8 sequential network requests:
     - `fetchCourses()` (all courses, modules, lessons)
     - `fetchAnnouncements()`
     - `fetchEnquiriesDb()`
     - `fetchSettings()`
     - `fetchTestimonialsDb()`
     - `fetchUsersDb()`
     - `fetchAllEnrollments()`
     - `fetchAllProgress()` (EVERY lesson progress record for EVERY user in the database!)
     - `fetchAllAttempts()`
     - `fetchAllCertificates()`
     - `fetchAllPayments()`
- Flow Lag Impact: Each lesson click produces 1-3 seconds of network congestion and heavy JSON parsing.
  On high-latency or mobile connections, this causes noticeable UI freeze and spinner stutter.

4.2. Unpaginated Database Queries & Memory Bloat
------------------------------------------------
- In `src/services/progressService.js`:
  `fetchAllProgress` performs `supabase.from('progress').select('user_id, course_id, lesson_id, completed')`
  with ZERO pagination, limit, or user scoping.
- In `src/services/paymentService.js`: `fetchAllPayments` fetches the entire table.
- In `src/services/assessmentService.js`: `fetchAllAttempts` fetches every quiz attempt ever recorded.
- Flow Lag Impact: As the platform grows to thousands of users, downloading tens of thousands of rows on
  every page transition will exhaust mobile browser memory and crash the JavaScript thread.

4.3. Realtime Postgres Changes & Broadcast Storms
-------------------------------------------------
- In `src/stores/lmsStore.js` (lines 1308-1360):
  Supabase Realtime listens to `postgres_changes` on `enquiries`, `announcements`, and `enrollments`.
- When an event occurs, it executes `debouncedSync()` with a 300ms timer.
- Flow Lag Impact: If 10 students enroll simultaneously during a workshop launch, 10 realtime events fire
  in rapid succession, triggering multiple concurrent `syncFromSupabase()` cycles that race against each
  other and overwrite React component states mid-render.

4.4. Video Streaming Latency & Player Blinking
----------------------------------------------
- In `src/features/courses/players/VideoPlayer.jsx`:
  When a student navigates between lessons, the player unmounts and remounts `Hls.js`.
- If Bunny CDN transcode is in progress or experiencing edge replication delay, Hls.js triggers
  `manifestLoadError` (HTTP 403 / 404). The player enters an error state requiring manual "Retry Connection".
- Flow Lag Impact: For external video embeds (YouTube / Bunny iframe), `onComplete` is never fired because
  there is no `postMessage` event listener attached to the iframe window. Students must manually realize
  they need to find and click "Mark Complete".

4.5. Layout Thrashing & UI State Inconsistencies
------------------------------------------------
- Duplicate Route Definition: In `src/routes/index.jsx`, `/app/learning/:courseId` is defined BOTH inside
  the `<UserLayout>` route hierarchy (line 95) AND as a standalone route outside `<UserLayout>` (line 104).
  Depending on React Router's internal route ranking, this causes conflicting layout mounting and redundant
  component renders.
- Mobile Sidebar Glitch: On viewports < 1024px, the sidebar closes whenever `selectItem` is called. If a
  student taps a lesson to inspect its duration, the sidebar immediately disappears, requiring repeated taps
  on the hamburger icon to navigate.

5. MODULE-BY-MODULE AUDIT: WORKFLOW, CODEWISE LOGIC, PROS, CONS & LACK OF LOGIC
====================================================================================================

----------------------------------------------------------------------------------------------------
5.1. Authentication & Security Middleware
----------------------------------------------------------------------------------------------------
- Files: `src/contexts/AuthContext.jsx`, `src/routes/ProtectedRoute.jsx`, `src/routes/AdminRoute.jsx`,
  `src/lib/apiClient.js`.
- Workflow:
  1. Boot check via `apiClient.auth.me()` against Supabase session.
  2. Subscribes to `supabase.auth.onAuthStateChange`.
  3. Tracks 3600-second idle inactivity timer with document interaction listeners.
  4. Role validation: `AdminRoute` verifies `user.role === 'ADMIN'`.
- Codewise Logic:
  - `lastActivityRef` records `Date.now()`. Event listeners on `mousemove`, `keydown`, `mousedown`,
    `touchstart`, and `scroll` update `lastActivityRef` throttled to 10 seconds.
  - Interval timer checks remaining seconds: if `<= 300`, sets warning flag; if `<= 0`, invokes `signOut()`.
- Pros:
  - Strict idle session timeout prevents unauthorized access on shared gym workstation computers.
  - Smooth integration of `onAuthStateChange` keeps auth state synchronized across browser tabs.
  - Throttled event listeners prevent scroll-jacking performance degradation.
- Cons:
  - Hardcoded admin email credentials (`admin@gmail.com` / `admin@123`) seeded directly into localStorage
    by `initLocalUserDatabase()`.
- Lack of Logic:
  - IN `lmsStore.js` (line 1528):
    `const isAdmin = !user || (user.role && user.role.toString().toLowerCase() === 'admin');`
    CRITICAL FLAW: `!user` evaluates to `TRUE`! An unauthenticated guest browsing the site is evaluated
    as an administrator during initial sync, triggering admin-level data fetching routines (`fetchAllEnrollments`,
    `fetchAllCertificates`, `fetchAllPayments`)!

----------------------------------------------------------------------------------------------------
5.2. Course Catalog & Public Landing Page
----------------------------------------------------------------------------------------------------
- Files: `src/features/landing/LandingPage.jsx`, `src/features/courses/CourseDetails.jsx`.
- Workflow:
  - Public visitors browse certified programs, filter by category, view pricing, and submit inquiries.
- Codewise Logic:
  - Live courses are fetched from `courseService.fetchCourses()`. Testimonials are loaded from
    `testimonialService.fetchTestimonials()`.
  - Inquiries submit via `enquiryService.submitEnquiry` writing to `enquiries` table with fallback to
    `_lms_mock_enquiries`.
- Pros:
  - High conversion design with authoritative fitness certifications (NASM, CFR PRO).
  - Smooth horizontal course card carousel with custom navigation buttons.
  - Responsive inquiry modal with auto-resetting form fields.
- Cons:
  - Heavy image assets directly in bundle without responsive `srcset` or dynamic CDN resizing.
- Lack of Logic:
  - In `LandingPage.jsx`, courses are filtered by `c.published !== false`. If an admin creates a course
    and forgets to set published = true, it still displays in some views because default is inconsistent
    between mock (`published: true`) and SQL (`published: false`).

----------------------------------------------------------------------------------------------------
5.3. Payments & Razorpay Integration
----------------------------------------------------------------------------------------------------
- Files: `src/services/razorpayService.js`, `src/services/paymentService.js`, `src/features/courses/CourseDetails.jsx`.
- Workflow:
  1. Student initiates enrollment on paid course.
  2. `openCheckout()` loads Razorpay SDK and opens checkout modal.
  3. Client receives payment ID upon successful card/UPI transaction.
  4. Client writes record to `payments` table and `enrollments` table.
- Codewise Logic:

----------------------------------------------------------------------------------------------------
6.1. Fatal Cascade Deletion of Student Progress on Course Edit [STATUS: RESOLVED / PATCHED]
File: `src/services/courseService.js` (lines 462-550)
Original Vulnerability: When an admin updated a course, it executed:
`await supabase.from('modules').delete().eq('course_id', courseId);`
`await supabase.from('assessments').delete().eq('course_id', courseId).eq('is_final', false);`
Because `lessons`, `progress`, and `attempts` had foreign keys with `ON DELETE CASCADE`, this wiped out
all student completion records and quiz attempt history for the entire course upon every course save.

Remediation Applied:
Implemented differential synchronization:
1. Queries existing modules and lessons for `courseId`.
2. Upserts all retained modules, lessons, and module quizzes by stable UUIDs (`onConflict: 'id'`).
3. Retains lesson identity so foreign keys in `progress` and `attempts` remain completely undisturbed.
4. Selectively deletes ONLY lessons, modules, and quizzes that were explicitly removed by the administrator.
Result: Course updates, title edits, price adjustments, and lesson additions now preserve 100% of student
progress records and quiz attempt histories.

6.2. Client-Side Exam Grading & Plaintext Answer Key Exposure [STATUS: RESOLVED / PATCHED]
File: `src/features/courses/players/AssessmentPlayer.jsx`, `src/services/assessmentService.js`, `api/submit-assessment.js`, `supabase_migration.sql`, `vite.config.js`
Mechanism: Previously, the question payload in client memory contained `isCorrect: true` on each option and model explanations before submission, allowing users to inspect answers via DevTools. In addition, grading math and pass/fail evaluation ran entirely on the client, trusting user-submitted scores.
Remediation (Applied):
1. Sanitized questions rendered during the quiz in `AssessmentPlayer.jsx`: stripped `isCorrect`, `correctIndex`, and `explanation` from client memory during examination.
2. Created PostgreSQL stored procedure `submit_assessment(p_course_id, p_module_id, p_assessment_id, p_answers, p_is_final)` in `supabase_migration.sql` (`SECURITY DEFINER`) to calculate scores, record attempts, and release certificates at the database layer.
3. Created serverless grading endpoint `api/submit-assessment.js` and wired it into Vite development middleware in `vite.config.js`.
4. Updated `submitAssessment` in `src/services/assessmentService.js` to execute secure backend evaluation and return sanitized post-exam review only after final submission.
5. Added submission loading states and disabled inputs during grading evaluation.

6.3. Unverified Public Certificate Page Failure [STATUS: RESOLVED / PATCHED]

2. Added an asynchronous verification lifecycle with an official credential loading state (`[ Verifying Official Accreditation Credential... ]`)
   to prevent UI flashing.
3. Enhanced `verifyCertificate` in `certificateService.js` to return complete credential metadata including exam score from

4. Added a `[PUBLICLY VERIFIED]` badge on the credential seal when verified directly through the Supabase public ledger.
Result: External employers and verifiers can now publicly inspect, verify, and print official certificates without needing to log in.

6.4. Triple Payment & Duplicate Enrollment Creation Bug [STATUS: RESOLVED / PATCHED]
File: `src/features/courses/CourseDetails.jsx` (lines 126-156), `src/hooks/useEnrollments.js` (lines 47-75)
Original Vulnerability: When enrolling in a course, `CourseDetails.jsx` explicitly called `enrollInCourse(course.id, user.id, paymentPayload)`

and then directly called `createPayment` and `enrollUser` a third time. Because `payments` uses `gen_random_uuid()` with no

2. Removed redundant `createPayment` and `enrollUser` side-effects from `useEnrollments.js`.
3. Removed the duplicate direct `enrollInCourse` call in `CourseDetails.jsx`, leaving `enrollMutation.mutateAsync` as the single executor.
Result: Each enrollment now triggers exactly one optimistic UI update, one Supabase payment insertion, and one Supabase enrollment upsert.

6.5. Unauthenticated Guest Treated as Administrator [STATUS: RESOLVED / PATCHED]
